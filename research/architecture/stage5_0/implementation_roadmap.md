# Implementation roadmap and approval gate

**Stage 5.1 proposal | Conditional GO after approval**

1. Introduce `pmi_core/schemas/bim.py`, `pmi_core/adapters/ifc.py`, `pmi_core/bim/elements.py`, `pmi_core/bim/quantities.py`, `pmi_core/bim/materials.py` and `pmi_core/validation/bim.py` only as needed by the slice. Define an import result with raw file digest, version ID, typed element/material/quantity records and issues. Prototype with IFC4 files and an explicit unsupported-schema error. Pin tested ifcopenshell in a future approved packaging step.
2. Adapt `base_class` and `_storey` in `research/ifc_to_gantt/extract_elements.py` to retain subschema class and parent hierarchy. Use `scripts/detect_changes.py` material/property readers as candidate extraction references, `scripts/export_geometry.py:make_settings` and `research/ifc4d/viewer_data.py:meshes` for placement and mesh diagnostics, and `research/ifc4d/pipeline.py:digest` for streaming hash behavior. Reuse established IfcOpenShell calls. Keep old entry points and outputs intact. Rewrite the takeoff adapter where legacy `_quantities` infers or collapses measurement basis. Preserve direct quantity entity, set, original unit, project unit resolution and normalized value. Detect disagreement and preserve all candidates.
3. Build fixture-only import and unit checks first. Required Section A evidence for release includes multiple independent authorized models with audited IFC versions, unit assignment and overrides, class/zone/material coverage, manually checked gross/net volume, area and mass, known missing data, geometry/quantity agreement and documented exporter quirks. Include an aligned revision pair and GlobalId persistence evidence for later revision release. Review evidence and tolerance thresholds with the engineering owner. Run on Restage and other eligible real models only under the reviewed evidence plan.
4. Proposed unit tests cover millimetre to metre with squared/cubed conversion, explicit quantity-unit override, imperial conversions, duplicate GlobalId, missing/ambiguous quantities, missing material, nested containment and coordinate placement. Integration tests cover synthetic snapshot import, deterministic re-import, source immutability and a reference quantity reconciliation with independent manual takeoffs. Report coverage by IFC class and quantity kind, causes of exclusions and performance. Approval requires reproducible reports and explicit limits on supported IFCs and takeoff methods.

Subsequent slices are 5.2 construction knowledge and provider, 5.3 engineering durations, 5.4 CPM and resource scheduling, 5.5 revision impacts and compatible cost/carbon ledgers, 5.6 correction interface gated NO-GO, and 5.7 supported scenario optimization and export. Later app work depends on stable contracts. Section A limits 5.1 real-model support, 5.2 spatial/quantity mappings, 5.3 quantity-backed estimates, 5.4 site/spatial rule validation, 5.5 identity/revision quality, and downstream 5.7 coverage and export claims. Synthetic validation can progress independently after approval. Sequence and stage boundaries are proposed planning decisions.

The source request ends after “Unit.” This proposal includes unit testing as the likely intended continuation.
